Quickstart

Connect a repository and a cluster, then deploy a new service from a golden path. This takes about 15 minutes.

Before you start You need admin access to a GitHub or GitLab organisation, and kubectl access to a Kubernetes 1.27+ cluster.

Install the CLI

The CLI is a single binary for macOS, Linux and Windows.

# macOS and Linux
brew install switchyard/tap/sy

# or with the install script
curl -fsSL https://get.switchyard.dev | sh

Then sign in. This opens your browser and uses your organisation's SSO if it's configured.

sy login

Connect Git and your cluster

Install the Switchyard app on your Git organisation, then install the runner in your cluster. The runner makes only outbound connections, so no inbound firewall rules are needed.

sy connect github --org acme
sy runner install --cluster prod-eu --namespace switchyard
Your code stays in your cloud The runner builds and deploys inside your cluster. Switchyard's control plane receives metadata such as service names, statuses and timings, never source code or secrets.

Create a service from a golden path

List the golden paths available to you, then create a service from one:

sy paths list
sy create orders-api --path node-service --owner team-fulfilment

Switchyard creates the repository, CI workflow, Helm chart and dashboards, and adds a switchyard.yaml to the repo:

service: orders-api
path: node-service@4.2.0
owner: team-fulfilment
deploy:
  strategy: canary
  regions: [eu-west-1]

Deploy it

  1. Open a pull request on the new repo. A preview environment link appears as a check within about 90 seconds.
  2. Merge the pull request. The canary rolls out to 5% of traffic, verifies, then completes.
  3. Run sy status orders-api to watch the rollout from your terminal.
